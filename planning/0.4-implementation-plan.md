[ADR 0013](../docs/adr/0013-coherent-token-model.md) (D1–D13), its accepted slices
[0010](../docs/adr/0010-graph-tokens-compose-last.md),
[0011](../docs/adr/0011-visibility-preserving-overrides.md), and
[0012](../docs/adr/0012-single-hyphen-css-variable-names.md), plus
[ADR 0014](../docs/adr/0014-material3-layer-and-mode-mapping.md). Where older records or the dated
[audit](../docs/audit-2026-09.md) differ, the accepted records control. In particular,
[ADR 0009](../docs/adr/0009-core-contract-convergence.md) is superseded where 0013 says so;
[0005](../docs/adr/0005-material3-adapter-package-boundary.md) and

[0008](../docs/adr/0008-material3-fragment-layer-type.md).

This record lives outside `docs/` because the repository's public-documentation gates treat new
undated files there as descriptions of the **currently shipped** API. Candidate implementation

## Dependency graph and cutover rule

```text
P0 TypeScript 7 + frozen 0.3 oracle
  -> P1 expression/resolver preparation
  -> P2 single core v2 runtime/wire cutover
  -> P3 static type contract and declaration proof
  -> P4 CSS activation exporter
  -> P5 Material layer API and packed pair
  -> P6 real-consumer migration and candidate docs
  -> P7 candidate evidence and versioning

P2 + P4 -> P4a optional var() output -> P6, if included
```

P0 precedes the type redesign because 7.x is the supported compiler and the emitted declaration
must work at both 7.0 and the repository's stable 7.x. P1 replaces the existing resolver with one
engine that still handles old literal/reference cases; it prepares canonical `concat` and the
pre-allocation bound without exposing a second public expression language. P2 is the necessary
public cutover transaction: canonical v2 source representation, one validator/composer, v1 source
upgrade, v2 compilation/metadata/parser, schemas, serialization, and removed authoring aliases
must agree in one reviewable milestone. Do not temporarily publish v2 source with a v1 compiled
writer, or route trusted and parsed inputs through different semantics. P3 then proves the static
view of that runtime, including the finite public union. P4 consumes compiled values and retained
expressions; Material can use the core layer contract after P3, but its existing packed consumer
also asserts CSS behavior, so migrate it after P4. P6 uses the paired tarballs only after both
packages agree. No intermediate phase is a publishable release.

Keep the active package pair testable at each public milestone. At P2, update the still-shipped
Material adapter's tests and packed assertions only where core v2 output changed; do not implement
the new Material API early or keep an old core semantics branch. At P4, update its CSS expectations
and README snippets to the actual exporter. P5 then replaces the adapter API in one step. Run the
nearest affected package gates after each phase and the full umbrella at the stable candidate.

## Phases

### P0 — TypeScript baseline and v1 oracle (internal preparation)

**Completed 2026-09-30.** Repository and 7.0 floor are both TypeScript `7.0.2`; the blocking
runner deduplicates them until they differ. `typescript@next` is a separate non-blocking CI signal.
The offline published-0.3.0 oracle is `tests/oracle/published-0.3.0.json`, generated from the
verified npm tarball with fixed seed `0x40302026` and 2,000 cases. TypeScript 7 required
`tsdown@0.23.0`; the docs site uses syntax-highlighted examples checked by the packed TypeScript 7
docs gate because its former Twoslash plugin requires the removed TypeScript 6 compiler API.

- **Entry/dependencies:** clean accepted-design `dev`; no source semantics changed.
- **Goal/decisions:** establish D13's supported `>= 7.0 < 8.0` major and a reliable old-semantics
  comparison before changing parsers. Resolve and pin the latest stable 7.x in root, Material and
  docs-site manifests/lockfile; do not bump `tsdown`, VitePress or Shiki incidentally. Keep Node
  `>=24`, Node 24/26 CI and direct pnpm. Add dedicated strict/NodeNext type configs and a
  version-selecting compatibility runner for latest 7.0 patch, repository stable 7.x (blocking),
  and `typescript@next` (non-blocking signal); use the same cases against packed declarations.
- **Likely files/deletions/API:** `package.json`, both workspace manifests, `pnpm-lock.yaml`,
  `docs-site/package.json`, `scripts/check-docs-site.ts`, `.github/workflows/ci.yml`, type configs,
  and a narrowly named new type-matrix script. Remove assumptions that `6.0.3` is the repository
  compiler. No new runtime export or production dependency.
- **Tests and exit:** freeze representative valid v1 graph/layer artifacts and expected outputs
  from the actual `0.3.0` tarball, including graph/layer collisions, explicit/default visibility,
  mode order and references. Seed and record the randomized equivalence corpus before cutover;
  run the old compiler, never the future parser, as its oracle. `pnpm validate`, `pnpm docs:check`,
  and existing packed gates pass with the 0.3 API; both blocking compilers pass the old case suite,
  while `next` reports without blocking. Changeset: none if only dev tooling/evidence changes;
  the published TypeScript support statement and its core changeset land at P2/P3.

### P1 — Canonical expression and resolver groundwork (internal)

**Completed 2026-09-30.** `src/core/canonical-expression.ts` owns normalization and original
reference-part paths; `src/core/resolve-expressions.ts` owns iterative, per-mode memoized DAG
resolution, replacing `resolveNode`/`unwind`. Public v1 grammar, diagnostics, metadata, API
snapshots and schemas remain unchanged; the frozen 0.3 oracle passes. The 65-token doubling
test observes every resolver join: `t13` builds 65,536 UTF-16 code units, `t14` fails before
joining, and dependants emit no additional issue. Core/workspace validation, stable/next type
compatibility, docs and the complete release gate pass. No changeset or public cutover in P1.

- **Entry/dependencies:** P0 oracle and compiler matrix recorded.
- **Goal/decisions:** implement D5's string/`{ ref }`/flat `{ concat }` canonicalizer and replace
  the current linear reference resolver with one iterative, memoized DAG resolver. Keep it behind
  the existing input boundary until P2. Normalize adjacent literals, empty parts, all-literal
  results (including `""`), and lone references; reject empty and nested concat. Detect unknown
  targets/cycles at their source, allow repeated sibling references, and stop dependants after a
  failed dependency. Sum part lengths before any join; `MAX_RESOLVED_VALUE_LENGTH` is 65,536
  UTF-16 code units for resolved concat values only. Keep the constant internal.
- **Likely files/deletions/API:** focused expression/resolution internals under `src/core/`,
  `compile-token-graph.ts`, and narrow unit/property tests. Delete the pure-reference-only
  `resolveNode`/`unwind` path rather than retaining two resolution algorithms. No public export
  or v1 grammar change yet.
- **Tests and exit:** focused DAG cases and exponential 65-token doubling chain prove the longest
  allocated value is at most 65,536; unknown/cycle pointers, sibling order, single failure, and
  literal input over the limit are explicit. Existing 0.3 behavior and `pnpm validate:core` pass.
  Changeset: none while the public result and accepted inputs are unchanged; add one if this phase
  intentionally changes a published diagnostic.

### P2 — Core v2 semantic and wire cutover (breaking/public)

- **Entry/dependencies:** P1 resolver and P0 old-semantics oracle; commit as one coherent core
  milestone, with no release between internal steps.
- **Goal/decisions:** implement ADR 0013 D1–D3, D5–D6, D9–D12 plus ADRs 0010/0011. Make
  `defineTokenGraph({ ... })` the only graph helper, keep `defineTokenLayer`/`tokenRef`, add
  `tokenConcat` and `orThrow`, delete `defineTokens` outright. Use one canonical graph/layer
  representation and validator for authoring and parsing, with authored pointers translated at
  each entry boundary. Normalize before validation; preserve authored mode order and explicit
  visibility until layers compose in array order and graph tokens compose last. Derive each layer's
  mode set from its maps, reject intra-layer disagreement first, then compare finite non-empty
  sets to the graph; invariant-only layers fit all graphs. Emit one `layer-mode-mismatch` per
  invalid layer with D12's fields/order/pointers, suppress implied per-token mode issues, and
  resolve references only after final composition. Metadata other than visibility comes solely
  from the winner.
- **Root runtime surface:** exactly `defineTokenGraph`, `defineTokenLayer`, `tokenRef`,
  `tokenConcat`, `parseTokenGraph`, `parseTokenLayer`, `parseCompiledScheme`,
  `compileTokenGraph`, `exportCssVars`, `serializeTokenGraph`, `serializeTokenLayer`,
  `serializeCompiledScheme`, and `orThrow`. Do not add aliases or expose the new internal pipeline.
- **Wire and migration:** all writers emit v2. Strict v2 graph/layer/compiled parsers use
  `kind` + `formatVersion`; `$schema` is optional uninterpreted string, copied verbatim except when
  upgrading v1 source. Implement exactly one pure v1→v2 graph step and one layer step before
  current validation. Preserve old values/visibility despite graph-last order by moving v1 graph
  declarations shadowed by layers into a deterministic leading layer and making visibility
  explicit only where old and new semantics differ. Ensure a generated layer id cannot collide
  with source ids; retain original-input issue paths. Never migrate v1 compiled output: reject it
  with `invalid-format-version` and a recompile instruction. Do not keep a second 0.3 parser or
  old-format writer.
- **Schema identity:** publish self-contained v2 files with these exact `$id` values, and only
  fragment `$ref`s:

  ```text
  tag:maikel.site,2026-09-29:scheme-tokens/schema/token-graph/v2
  tag:maikel.site,2026-09-29:scheme-tokens/schema/token-layer/v2
  tag:maikel.site,2026-09-29:scheme-tokens/schema/compiled-scheme/v2
  ```

  The `maikel.site` authority prerequisite was confirmed in D10. Published source artifacts may
  use an exact-package-version HTTPS `$schema` editor hint, but the parser never reads it as
  authority. The package exports only current-version schema files.

- **Compiled representation:** v2 `tokens` stay resolved values. Replace metadata `origin` and
  `dependenciesByMode` with ordered non-empty `declarations` and sparse `expressionByMode`.
  Literals have no expression entry; pure refs retain only `ref`; concat retains ordered parts,
  with each referenced part's resolved value. The composed declaration path records explicit
  visibility on each declaration; final visibility is separate. Serializers preserve canonical
  expressions and authored mode order.
- **Likely files/deletions/API:** `src/core/graph.ts`, `parse-token-graph.ts`,
  `compile-token-graph.ts`, `compiled-types.ts`, `parse-compiled-scheme.ts`, `result.ts`,
  `src/exporters/serialize-scheme.ts`, `src/index.ts`, all three `schemas/*.v2.schema.json`,
  schema tests/fixtures, unit/property tests, `api/scheme-tokens.api.d.ts`, root package schema
  exports, `scripts/check-api.ts`, `check-tarball.ts`, `check-module-resolution.ts`, and old
  `defineTokens` consumers under `examples/`/`scripts/`; update Material tests that read the old
  compiled fields. Remove v1 schema subpaths/files from
  the **current package**; keep frozen v1 evidence only in tests or old published tarballs. Remove
  superseded root type/field shapes and duplicated validators. The root runtime export list must
  be precisely D2's 13 names; update its export gate, not merely the barrel.
- **Tests and exit:** table-driven normalization, layer equality and mismatch, provenance,
  Result/cause shape, structured issue fields, v2 schema-id and self-contained-ref checks,
  strict version rejection, `$schema` neutrality, v1 fixture plus seeded 2,000-graph source
  equivalence (values and visibility, with collision cases), and parse/serialize determinism.
  Capture current source metadata through upgrade without silently dropping authored fields.
  Update README, public API/architecture/diagnostics and relevant docs-site examples at this
  cutover so they describe the branch's actual runtime surface; do not present P3's complete
  public typing or P4's CSS model as already implemented. Gate with focused suites, then
  `pnpm validate:core`, `pnpm test:schemas`, `pnpm docs:check`, API snapshot/check and
  `pnpm check:changeset`. Add a core **minor** changeset covering changed public behavior and
  source/compiled wire contracts. Exit only when no authoring/parser/compiler/writer path retains
  v1 semantics for new input.

### P3 — Static contract and packed declaration proof (breaking/public)

- **Entry/dependencies:** P2 runtime and stable 7.x compiler. No type may promise more than P2
  returns at runtime.
- **Goal/decisions:** implement D4/D12/D13's `TokenGraph<Key, Mode, PublicKey>` and
  `TokenLayer<Key, Mode, Visibility>` inference with the accepted plain `const` capture and
  validating constraint. Track explicit public/internal keys and defaults through layer order
  and graph-last override; a finite literal public union makes default/public compilation
  complete, dynamic/parsed graphs stay partial. `all` is complete only with a finite key union;
  exact literal tuples remain complete. Preserve reference typo suggestions, the accepted named
  marker diagnostics (including `LayerModeMismatch<LayerModes, GraphModes>`), and reject metadata
  mixed with mode keys. Settle public type exports by the emitted snapshot, without adding
  implementation plumbing.
- **Likely files/deletions/API:** `src/core/graph.ts`, `compiled-types.ts`,
  `compile-token-graph.ts`, `tests/types/authoring.test.ts`, new focused type cases, root snapshot,
  packed type-gate scripts, `docs-site/guide/typescript-access.md`, `docs/public-api.md`,
  `docs/semver.md`, `docs/development.md`, and candidate support wording. Delete old partial-public
  assertions and unbound-layer assumptions; do not weaken negative `@ts-expect-error`s.
- **Tests and exit:** literal/public, override-publication, unknown visibility, dynamic spread,
  parsed graph, exact/all, invariant/finite/dynamic layers, disagreement/mismatch, and the
  Appendix A diagnostic-quality cases pass with source **and emitted packed declarations** on
  latest 7.0 patch and repository stable 7.x. `typescript@next` remains signal. Profile the
  2,000-literal-token check on 7.0 against today's type cost. `pnpm validate:core`, API and packed

  snapshot in the same commit.

### P4 — CSS activation exporter (breaking/public)

- **Entry/dependencies:** P2 compiled v2; P3 types for the new option/result surface.
- **Goal/decisions:** implement D7 and ADR 0012 in `exportCssVars()`: single-hyphen default
  variable names, all collision issues with `firstKey`, `key`, `property` and a message naming all
  three; full selected-token declarations in every block; zero-specificity `:where()` activation
  selectors; base → system → explicit → custom tiers, authored mode order within a tier and
  condition order within a mode. Base targets `root` (default `:root`), system is an optional
  media condition at root, explicit uses one attribute (default `data-theme`, `false` disables),
  and custom selectors may carry bounded media. Explicit markers include the default mode, are
  unanchored and nest; `:host` emits host and inside-shadow selectors. Implement `cascadeLayer`
  wrapping and block metadata (`tier`, `mode`, `selectors`, optional `media`, `declarations`).
  Expand bounded selector/media validation as D7 states; keep custom-property-only output and
  declaration-safety checks. `color-scheme` stays an application-bound token.
- **Likely files/deletions/API:** `src/exporters/export-css-variables.ts`,
  `selector-validation.ts`, CSS tests, `tests/properties/determinism.test.ts`, root API snapshot,
  `scripts/check-api.ts`, `docs/` CSS/Tailwind/application-coordinate guides, docs-site CSS guide
  and packed theme-coordinate example, plus Material CSS examples/tests that exercise the old
  exporter. Delete `scope`, `modeSelectors`, `CssScope`,
  `classPrefix`, old strategy parsers and any generic `properties` path; classes use custom
  conditions. Keep `variableName` for genuine exceptions.
- **Tests and exit:** collision collection, default names, tier and within-tier order,
  complete-block invariant, non-mode attribute system fallback, overlapping custom conditions,
  nested dark/light islands, shadow-host selector shapes, `cascadeLayer` and safe grammar.
  Add a focused real-browser gate for Chromium, Firefox and WebKit; the repository has no current
  browser gate, so a targeted test harness is justified. Follow D7's documented unwrapped-host
  exception **only if** a browser fails `:where(:host)` or `:where(:host(...))` matching. Gate
  with focused unit/property tests, browser suite, `pnpm validate:core`, docs/API checks and the
  packed theme-coordinate consumer. Add a core minor changeset and snapshot diff.

### P4a — Optional `var()` output (additive, recommended for 0.4)

- **Entry/dependencies:** P2 retained expressions and P4 complete-block exporter. This phase is
  optional for 0.4 by ADR 0013's release scope; keep it separate from the breaking path.
- **Goal/decisions:** implement D8's `references: "var"` while resolved output remains default.
  Link a direct target only when that target is in the same export; otherwise inline its resolved
  mode value, including per-part concat fallback. Never infer dependencies by parsing strings.
- **Likely files/deletions/API:** CSS exporter/types, unit/browser tests, CSS guides, root snapshot;
  no new package. Add a core changeset if included.
- **Tests and exit:** stale-alias browser regression (ancestor declaration alone remains stale;
  redeclaring every alias in a nested mode block follows the target), pure-ref and concat links,
  internal-target inlining, and unlayered override behavior. Run P4 browsers and core API/docs
  gates. Recommend including it in 0.4 because D6 already supplies the needed per-part data and
  P4 already pays for complete blocks; omitting it would leave a tested accepted output semantic
  unused while the exporter is being rewritten. If its browser proof delays the breaking path,
  omit this phase and release it in a later 0.x minor without altering P2–P4.

### P5 — Material layer and mode mapping (breaking/public)

- **Entry/dependencies:** P2/P3 core layer and type contracts, P4 CSS naming/packed proof; P4a
  is required only if chosen for the candidate.
- **Goal/decisions:** implement ADR 0014 exactly. `material3(sourceColor, options?)` returns one
  ordinary `TokenLayer` with fixed id and the same 48 role keys, never a fragment. The positional
  source is the only global source. Optional `modes` is an exact, non-empty map from graph modes
  to settings; omitted means `{ light: {}, dark: {} }`. Only literal `light`/`dark` imply
  `colorMode`; custom names require it and built-ins reject it. Global `variant`,
  `contrastLevel`, source and `specVersion` follow 0014's defaults; per-mode overrides are only
  source, variant and contrast. `specVersion` and visibility stay global. Reject unsupported
  engine coordinates before generation; core owns mode grammar and structural failures, whose
  issue-tuple `cause` propagates unchanged. Keep adapter misuse as TypeError/RangeError. `NoInfer`
  on returned Mode/Visibility prevents contextual fabrication; `Material3Options` defaults Mode
  to `Material3ColorMode` and Visibility to `TokenVisibility`, while the function's inferred
  Visibility defaults to `"public"`.
- **Likely files/deletions/API:** `packages/material3/src/material3.ts`,
  `packages/material3/src/types/material3.ts`, barrel, adapter API snapshot/check,
  tests/types/integration/packed
  consumers, README and root Material examples. Delete `Material3GraphFragment`,
  `Material3Appearance`, additive/exact mode option types and code, `exactModes`, Material-owned
  `defaultMode`, `appearance`, fragment spread and two-stage graph validation. Update adapter
  gate to exactly six named type exports (`Material3TokenKey`, `Material3ColorMode`,
  `Material3SpecVersion`, `Material3Variant`, `Material3Modes`, `Material3Options`) and one
  runtime export. Do not export the per-mode settings type. Keep ADR 0007 engine/golden fixtures.
- **Tests and exit:** default and six-mode layers, per-mode overrides, source-color ambiguity
  rejection, empty map static/runtime rejection, capability matrix, one layer per graph,
  `LayerModeMismatch`, three contextual `NoInfer` cases, visibility default distinctions, exact
  exports, core error shape, engine golden vectors, combined/core-only strict Node ESM and
  NodeNext packed consumers. `pnpm validate:material3`, `pnpm release:material3:gates`, and root
  relevant API checks pass. Add a Material **minor** changeset and API snapshot diff. Change its
  peer range to `^0.4.0` in the release candidate and verify Changesets' transformed pair.

- **Entry/dependencies:** P3–P5, and P4a if selected. Use candidate tarballs; no consumer should

- **Goal/decisions:** migrate the repository's executable theme-coordinate example and packed

  `layers: [material]`, `exactModes` → `modes` checked with
  `satisfies Material3Modes<CompilerMode>`, `appearance` → `colorMode`, and removes Material
  `defaultMode` and hand-written mode-drift checks. Replace fragment spread wherever used;
  replace `defineTokens` calls with `defineTokenGraph({ tokens, ... })`; update provenance reads
  from `origin`/`dependenciesByMode` to declarations/expressions; recompile old compiled caches,
  parse and reserialize any persisted v1 graph/layer artifacts. Its CSS migration may replace the
  old naming callback with `prefix: "color"` and old selector map with
  `attribute: false`, `system` and custom conditions. Verify `color-scheme` bindings at every
  activated element. Demos replace fragment spread, `:root.dark` with a `.dark` custom condition,
  and optional throw boilerplate with `orThrow`; check nested behavior. Move each consumer to
  TypeScript 7. Record actual CSS/output diffs; distinguish package failures from unrelated
  consumer-repository gates.
- **Likely files/deletions/API:** repository examples and all packed/audit scripts, plus separate
  consumer repositories in their own implementation work. In this repository, switch README,
  `docs/public-api.md`, `architecture.md`, `diagnostics.md`, CSS and Tailwind guides,

  actual implemented status; preserve ADRs/audits as history. Remove superseded examples and test

- **Tests and exit:** packed theme-coordinate and external audit gates execute 0.4 forms;
  production site typecheck/build and relevant rendered CSS behavior pass against the paired
  tarballs; demos build and render basic/nested mode behavior. These are release gates, not
  background examples. Consumer changes carry their own repository delivery policy; core/adapter
  changesets are required only for additional published behavior discovered here. No external
