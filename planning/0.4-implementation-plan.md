Former external requirements are superseded; [historical P6 observations](../docs/p6-consumer-evidence.md) remain. P7 release preparation remains separate and unstarted. The accepted decisions are

[0010](../docs/adr/0010-graph-tokens-compose-last.md),
[0011](../docs/adr/0011-visibility-preserving-overrides.md), and

reservation of `concat`: it remains a valid mode name, distinguished structurally from a concat
expression by the exact one-property object with an array value. Where older records or the dated
[audit](../docs/audit-2026-09.md) differ, the accepted records control. In particular,
[ADR 0009](../docs/adr/0009-core-contract-convergence.md) is superseded where 0013 says so;

[ADR 0018](../docs/adr/0018-public-api-refinement.md) subsequently refined the candidate API. Completed-phase descriptions below retain their historical names and behavior; current implementation and release work must use the refined contract documented in the [public API](../docs/public-api.md).

Planning started on clean `dev` at `b1034b2` (`docs(adr): confirm the tag: authority and fix
tokenConcat examples`). The accepted-design history contains `ded9c50`, `d30e3b4`, `17df9f4`,

The intended candidate versions are core `0.4.0` and Material `0.2.0`, each a breaking pre-1.0
minor. The Material candidate should peer on `scheme-tokens: ^0.4.0` alone unless compatibility
with an older minor is separately proved; its new layer contract does not provide that proof.
Keep the engine at its exact `0.4.0` pin and preserve the 48-role and licensing gates.

## Dependency graph and cutover rule

```text
P0 TypeScript 7 + frozen 0.3 oracle
  -> P1 expression/resolver preparation
  -> P2 single core v2 runtime/wire cutover
  -> P3 static type contract and declaration proof
  -> P4 CSS activation exporter
  -> P5 Material layer API and packed pair
  -> P6/P6.1 package-owned integration, candidate verification and compiler evidence
  -> P7 candidate evidence and versioning

P2 + P4 -> P4a optional var() output -> P6, if included
```

P0 established the TS7 development toolchain before the type redesign. P6.1 adds independent consumer floors under ADR 0017; source and packed declarations must pass every supported role. P1 replaces the existing resolver with one
engine that still handles old literal/reference cases; it prepares canonical `concat` and the
pre-allocation bound without exposing a second public expression language. P2 is the necessary
public cutover transaction: canonical v2 source representation, one validator/composer, v1 source
upgrade, v2 compilation/metadata/parser, schemas, serialization, and removed authoring aliases
must agree in one reviewable milestone. Do not temporarily publish v2 source with a v1 compiled
writer, or route trusted and parsed inputs through different semantics. P3 then proves the static
view of that runtime, including the finite public union. P4 consumes compiled values and retained
expressions; Material can use the core layer contract after P3, but its existing packed consumer
also asserts CSS behavior, so migrate it after P4. P6 uses the paired tarballs only after both
packages agree. No intermediate phase is a publishable release.

Keep the active package pair testable at each public milestone. At P2, update the still-shipped
Material adapter's tests and packed assertions only where core v2 output changed; do not implement
the new Material API early or keep an old core semantics branch. At P4, update its CSS expectations
and README snippets to the actual exporter. P5 then replaces the adapter API in one step. Run the
nearest affected package gates after each phase and the full umbrella at the stable candidate.

is covered for native v2 and migrated v1 graphs and layers, preserving D10's retention promise.
The unchanged frozen 2,000-case oracle passes. Its current corpus needs 803 explicit visibility
assignments and 1,340 synthetic leading layers; the ADR's 772 assignments describe the earlier

The exact 13 exports, D6 metadata, v2-only schema subpaths, intentional core API snapshot and

### P3 — Static contract and packed declaration proof (breaking/public)

**Completed 2026-09-30.** `defineTokenGraph` returns `TokenGraph<Key, Mode, PublicKey>` and
`defineTokenLayer` returns `TokenLayer<Key, Mode, Visibility>`; both keep the P2 runtime fields
(`layers` and `$schema` stay optional) and add only type-level static facts (made nominal by the
review hardening below). Layer
`Mode` is `never`, a finite union, or `string`. The exported `LayerVisibility` records
`default` plus the keys that may declare `public`, declare `internal`, or be `omitted`. This
refines Appendix A's three-field prototype: with omission as an implicit complement, TypeScript's
subtype reduction of `cond ? internalLayer : publicLayer` kept only the public member and
promised a key the runtime can omit. With every state explicit, a wider type only adds
possibilities. Composition mirrors ADR 0011 over layer order and graph-last tokens, narrows each
layer's sets to its own keys, and treats union tuple elements and non-tuple layer lists as
dynamic. Finite key and public-key unions are exact claims, invariant among finite sets but
assignable to the `string` forms, and compilation distributes over graph unions.

Default and explicit `public` compilation are complete for a finite, fully known public union
and otherwise partial over every graph key; `all`, exact tuples, runtime arrays, parsed and
dynamic graphs follow D4, and CSS lookup completeness follows the input. Authoring uses plain
`const` capture with a strict constraint whose valid branch is `unknown`, so contextual
typing never expands the expected shapes. Keeping them in that branch cost about 0.4 s on the
2,000-token graph. Classification is structural per ADR 0015. `valueByMode`, other identifiers
outside the runtime grammar, and reserved names fail statically with `InvalidModeName`, and
`concat` stays valid. Layer modes use the same grammar. `tokenConcat` types its canonical result
by reference count. `layers` is constrained by a mode-free data shape, so an inline generic layer
is rejected without `NoInfer`. A local generator fixture shows `NoInfer` still needed for the
annotated-variable case that P5 owns. Markers stay unexported.

Evidence: the `tests/types` matrix (E1–E10, V1–V3, M7–M11, grammar, ADR 0015, visibility
chains, unknown/dynamic/parsed cases, exact claims) passes under the stricter and the
strict-only configuration. `pnpm check:packed-types` runs the same files against the packed
tarball in NodeNext with `skipLibCheck: false`, plus nine fragment-based diagnostic cases.
Floor and repository stable are both 7.0.2 and ran once. `typescript@next`
7.1.0-dev.20260929.1 passed as signal. `pnpm profile:types`, 11 paired runs on 7.0.2: P2 0.255 s
median, P3 0.150 s. Emitted core JavaScript is byte-identical to P2, the oracle and runtime
suites are unchanged, and the only new root type export was `LayerVisibility`. The core snapshot
and the `core-v2-static-contract` minor changeset landed together. Material needed one
source-only type assertion for core's validated layer copy; its emitted JavaScript and API
snapshot are unchanged, so it has no changeset.

**Review hardening, 2026-09-30.** Review found that the optional phantoms let an annotated object
literal claim graph keys, public keys, modes, or layer keys and visibility that its data did not
prove; a spread copy with another `defaultVisibility` also kept a stale public set. All of these
compiled on `9daf088` and failed at runtime. `TokenGraph` and `TokenLayer` are now aliases of
their field interfaces plus, for any claim narrower than the plain form, the unexported
`StaticProof`, whose `#private` member has no runtime counterpart: only the helpers' signatures
supply it, and object literals, spread copies, and mapped types lack it. The plain forms still
accept raw data, helper values stay assignable to their exact claims and to every plain form,
different finite claims stay incompatible, and the four-field `LayerVisibility` still keeps union
members distinct. Unproven layers compose as dynamic, so an inline layer may declare any key.
`defineTokenGraph` returns the new exported `DefinedTokenGraph`, whose own authored keys are
definite in `graph.tokens` while layer-only keys are not promised there; `Key` still names every
composed key and `all` stays complete. The name is needed because an anonymous intersection
with the unexported proof cannot be named in a consumer's emitted declarations. Matching a bare
`string extends Key` check inferred `string` for structurally matched graphs, so `GraphTokens`
checks through `IsDynamic`. `tests/types/static-claims.test.ts` fails on `9daf088` at every
forgery and passes in the source and packed matrices; the packed stricter consumer now also
emits declarations, and two packed diagnostics require the missing `StaticProof` to be named.
Core emitted JavaScript is byte-identical to `9daf088`; Material's source, JavaScript,
declarations, and API snapshot are unchanged, and its assertion remains because core types
`graph.layers` without key sets. Interleaved `pnpm profile:types` runs (11 each, 7.0.2): 0.194 s
median against 0.177 s for the P3 declarations on the same machine.

**Final review hardening, 2026-09-30.** Review raised two concerns against `52e062a`. First,
`Object.assign` keeps a stale proof. Without assertions, on the source and on the packed declarations
with 7.0.2, `Object.assign({}, graph, { defaultVisibility: "internal" })` of a graph with
`tokens: { implicit: "a", explicit: { value: "b", visibility: "public" } }` keeps
`PublicKey = "implicit" | "explicit"`, and the default compilation types `tokens.implicit` as
definite; at runtime it is absent, so reading its mode throws a `TypeError`. The same stale proof
survives replacing graph `tokens` or `layers`, a layer's `tokens`, or a widened layer default, and a
literal graph default, whose field type is `TokenVisibility`. Mode rewrites keep no finite stale
mode: a widened override infers `string`, and a conflicting literal collapses the type to `never`.
A copy without overrides keeps a sound proof. No local type fix exists. The library declares the
merge as `T & U`, and TypeScript relates an intersection to each of its members, so the result is
assignable to the helper's own precise type whatever the proof is made of. After one annotated
assignment it is identical to the helper type, so no check in `compileTokenGraph` or layer
composition can tell them apart. In-place `Object.assign(graph, …)` mutates an unfrozen helper
result and leaves the type of `graph` unchanged. A literal field tied to the claim collapses only
literal overrides, and to `never`, which is assignable to every claim. Recomputing facts from the
fields still reads the intersected original fields. Only runtime identity or a different API could
detect such a rewrite, so both are outside this phase. The contract therefore draws a boundary.
Values that flow unchanged from the helpers keep valid precise facts through assignment and
parameters. Raw values, spread copies, and mapped copies are dynamic. Assertions, mutation through
aliases or `any`, and intersection-typed rewrites that replace semantic fields are outside the
guarantee. Changed semantics need a new `defineTokenGraph` or `defineTokenLayer` call, and persisted
data goes through the parsers. The public docs and the changeset state this boundary; no API
was added.

Second, the `#private` marker was suspected of setting a target floor. It sets none within the
supported range. TypeScript 7.0.2 removed `target: ES5` (TS5108 from `tsconfig`, the CLI, and
`ignoreDeprecations` "6.0" or "7.0"), and the packed declarations typecheck with
`skipLibCheck: false` at ES2015, including its default library, and at ES2022. Outside the
contract, 6.0.3 at ES5 reported TS18028 for it. A classic `private proof` member matched every
listed property. However, `"proof" in value` then narrowed helper graphs out of the false branch,
which is where they run, and `typeof graph & { proof?: string }` collapsed to `never`, so it was
rejected. `StaticProof` now has `private [staticProof]`, keyed by an unexported `unique symbol`.
It matched `#private` on every measured property, source and packed:

- foreign `#private` and classic proofs are rejected;
- raw objects, plain and overriding spreads, and `Readonly`, `Pick`, `Omit`, and `Required` copies
  lose it;
- exact claims still reject each other and still assign to the plain forms;
- union reduction, consumer declaration emit, `in` narrowing, and `keyof` are unchanged.

The declarations carry no target-gated syntax; 6.0.3 at ES5 now passes, as out-of-contract
evidence only. New `static-claims` cases cover the plain spread, `Pick`, foreign proofs, `in`, and
name conflicts. They fail against the string-named marker and against a non-nominal one. The API
check pins the marker fragment. No low-target gate was added: no in-contract dependency exists, and
a 7.x ES2015 check would accept `#private` anyway. The source and packed matrices, 11 diagnostics,
and the 7.0.2 compatibility run pass. Core JavaScript is byte-identical to `52e062a`, and Material is
unchanged. `pnpm profile:types 11`, interleaved on 7.0.2: medians 0.201–0.210 s, against
0.206–0.209 s for `52e062a`.

milestone branches exist in this checkout. Follow `AGENTS.md`'s `dev` rule: land P0/P1 and then
each coherent milestone as atomic Conventional Commits on `dev`, with a scoped changeset at each
public boundary. Review each commit's source, snapshot, tests and docs together. Keep P2's source
and compiled v2 cutover in one review unit; do not merge a half-cutover and do not create a
parallel compatibility API. If PR review is required later, use short-lived milestone branches
targeting `dev`, preserving the same dependency order; do not carry independent long-lived core
and Material branches across the shared type cutover. Revert a complete milestone to roll back;
never reset or force-push shared history. This planning pass creates no branch or PR and does not
push.

## Risks that can survive a green unit suite

| Risk                                                                                                      | Detecting gate / mitigation                                                                                                                   |
| --------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Types claim public completeness for a key runtime visibility hides, or a dynamic set is treated as finite | P3 type cases paired with P2 runtime composition, all supported consumer compiler roles and packed declarations.                              |
| Explicit visibility is erased during normalization, so overrides inherit the wrong default                | P2 chain tests with both defaults and explicit changes, plus old-source equivalence corpus.                                                   |
| A layer's mode set is inferred from one map, from a direct expression, or from the graph's order          | P2 disagreement/equality runtime cases and P3 finite/dynamic marker cases.                                                                    |
| v1 input accidentally runs under graph-last/new-visibility semantics before upgrade                       | Frozen 0.3 tarball oracle, graph–layer collisions and visibility comparison in 2,000 seeded cases.                                            |
| Concat allocates an oversized string before checking or reports every dependant                           | P1 instrumented doubling DAG, UTF-16 boundary and single-source issue assertions.                                                             |
| Retained expression/provenance data duplicates or disagrees with resolved output                          | P2 sparse-expression, declaration-chain and v2 parse/serialize round-trip cases.                                                              |
| CSS tiers appear in the right text order but specificity/source order computes differently                | P4 three-engine computed-style suite, overlap/nesting/layer cases and complete-block assertions.                                              |
| `:where(:host)` differs across engines                                                                    | P4 Firefox/WebKit/Chromium shadow-root gate and the explicit D7 fallback only if needed.                                                      |
| Material generics infer six modes from context although only light/dark were generated                    | P5 annotated-variable, declared-return and typed-list `NoInfer` negatives against emitted packed declarations.                                |
| Source tests pass but consumer declarations or peer artifacts fail                                        | P3/P5/P6.1 supported-role source/packed type checks, strict peer paired tarballs, module-resolution and repository-owned coordinate runtimes. |

## Explicitly deferred

No DTCG import package, generalized expression language, CLI, plugin architecture, core color
model, per-mode Material `specVersion`, broader Material role/custom-color extensions, or
graph-wide resource budget. Also keep the D13 next-major signal non-blocking and the ADR 0013
deferred explain/layer-remapping helpers, contrast sibling package, `@property` registration and
further selector features outside this release. P4a is the only optional additive candidate phase;
its inclusion does not gate completion of the required breaking contract.
