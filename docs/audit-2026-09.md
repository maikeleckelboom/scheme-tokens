## 0. Framing

The roadmap plans `1.0.0` next and requires "an explicit unresolved contract blocker" for any
further pre-1.0 minor ([roadmap.md:57-59](./roadmap.md)). Section 1 lists contract changes that are
materially cheaper before 1.0 than after it; they are the candidates for such a blocker. Sections
2–5 are additive, type-level, or internal.

Consumer impact is small. `maikel.site`, the only known production consumer, composes a 48-token
`material3` layer whose keys never collide with its 338 graph keys, compiles with exact keys and with
`all`, and already names CSS properties through `variableName`. Of the section 1 proposals, 1.4
changes its exporter call, 1.5 changes its CSS block order because its authored mode order is not
canonical, and 1.6 renames its graph helper call.

## 1. Pre-1.0 contract decisions

### 1.1 Directly authored graph tokens lose silently to layers

Proposed decision: [ADR 0010](./adr/0010-graph-tokens-compose-last.md).

Evidence:

- Composition registers graph tokens first and layers afterward; a later declaration replaces an
  earlier one ([parse-token-graph.ts:233-268](../src/core/parse-token-graph.ts)). The order is pinned
  by [core-v1.test.ts:107](../tests/unit/core-v1.test.ts) and retained by
  [ADR 0009](./adr/0009-core-contract-convergence.md) and [roadmap.md:71-72](./roadmap.md).
- Probe A1: a graph token `brand.primary: "#ff0055"` composed with a layer that declares
  `brand.primary: "#6750a4"` compiles to `#6750a4`, with origin `{ kind: "layer", id: "generated" }`
  and no issue.
- With the documented fragment pattern, `defineTokenGraph({ ...material, tokens: { … } })`, an
  application token that shares a key with a generated role therefore has no effect. The README
  teaches overrides through an extra layer instead ([README.md:261-294](../README.md)).
- The documentation already anticipates the confusion: "This is token composition, not CSS cascade
  behavior" ([architecture.md:34](./architecture.md)).

Ecosystem expectation: in CSS cascade layers, unlayered declarations beat every named layer. Style
Dictionary's `source` tokens override `include` tokens, and preset systems apply the user's own
configuration last. The DTCG Resolver also lets the most recent occurrence win, but it has no
privileged "own tokens" position that is applied first.

Severity: High. Authored intent disappears without a diagnostic.

### 1.2 Overrides silently change visibility

Proposed decision: [ADR 0011](./adr/0011-visibility-preserving-overrides.md).

Evidence:

- A replacing declaration without an explicit `visibility` receives the `defaultVisibility` of its
  own composition position, which defaults to `public`
  ([graph.ts:782-787](../src/core/graph.ts),
  [parse-token-graph.ts:898-907](../src/core/parse-token-graph.ts)). The resulting flip from
  `internal` to `public` is pinned by [core-v1.test.ts:122-156](../tests/unit/core-v1.test.ts).
- The material3 README override example combines `visibility: "internal"` with an override layer
  that omits `defaultVisibility` ([packages/material3/README.md:84-96](../packages/material3/README.md)).
  Probe A2 reproduces that shape: `md.sys.color.primary` becomes public and CSS export emits
  `--md--sys--color--primary`.
- The root README avoids the leak only because its override layer sets
  `defaultVisibility: "internal"` ([README.md:275](../README.md)).

Recommendation beyond the ADR: correct the material3 README example whatever ADR 0011 decides.

Severity: High. An internal implementation token reaches public compiled and CSS output.

### 1.3 Default CSS names separate segments with `--`

Proposed decision: [ADR 0012](./adr/0012-single-hyphen-css-variable-names.md).

Evidence:

- The default encoder joins segments with `--` and the prefix with `-`
  ([export-css-variables.ts:687-693](../src/exporters/export-css-variables.ts)). Probe A11:
  `action.primary.background` with prefix `app` becomes `--app-action--primary--background`.
- Both known real naming configurations replace the default with `segments.join("-")`:
  `maikel.site` ([consumer evidence audit](./audit-2026-08-consumer-evidence.md)) and the material3
  README ([packages/material3/README.md:109](../packages/material3/README.md)).
- The Tailwind guide tells readers not to do exactly that
  ([tailwind-css-v4.md:12-15](./tailwind-css-v4.md)). The documentation contradicts itself.
- Injectivity does not depend on the double hyphen alone: collisions are already reported as
  `duplicate-css-variable` instead of overwriting a declaration
  ([export-css-variables.ts:221-235](../src/exporters/export-css-variables.ts)).

Ecosystem expectation: Style Dictionary (`name/kebab`), Terrazzo (dots replaced by hyphens),
Tailwind (`--color-red-500`), and Material (`--md-sys-color-primary`) use single hyphens.

Severity: Medium. The conventional output needs the documented advanced escape hatch.

### 1.4 CSS option shape and default selectors

Evidence:

- The exact strategy names the same concept three times:
  `modeSelectors: { strategy: "selectors", selectors: { … } }`.
- `scope: { strategy: "root" }` is equivalent to omitting `scope`
  ([export-css-variables.ts:565-579](../src/exporters/export-css-variables.ts)).
- Generated strategies anchor every non-default mode to the scope, `:root` by default
  ([export-css-variables.ts:422-425, 491-495](../src/exporters/export-css-variables.ts)). Probe A5
  yields `:root[data-theme="dark"]`, so a nested region such as a dark section inside a light page
  cannot switch modes with the generated strategies.
- The default attribute is `data-scheme`. The de facto convention is `data-theme`, the default
  attribute of next-themes.
- `scope` collides conceptually with the CSS `@scope` at-rule. Style Dictionary's `css/variables`
  format calls the equivalent option `selector`.

Recommendation: flatten the options with structural discrimination, as the token grammar already
does. Make the scope a plain selector string, stop anchoring non-default generated modes to `:root`,
and design the result together with mode conditions (3.1) so the option shape breaks once. A
non-normative sketch:

```ts
exportCssVars(scheme, {
  prefix: "app",
  selectors: {
    light: [":root", '[data-theme="light"]'],
    dark: [
      '[data-theme="dark"]',
      { media: "(prefers-color-scheme: dark)", selector: ":root:not([data-theme])" },
    ],
  },
  layer: "tokens",
});
```

Severity: Medium.

### 1.5 Authored mode order is discarded

Evidence:

- Modes are canonicalized to the default mode followed by the remaining modes in code-unit order
  ([graph.ts:445-450](../src/core/graph.ts),
  [parse-token-graph.ts:1301-1309](../src/core/parse-token-graph.ts), and the serializer). Probe A3:
  `["light", "dim", "dark"]` becomes `["light", "dark", "dim"]` in the graph and the compiled scheme.
- CSS blocks follow `scheme.modes`
  ([export-css-variables.ts:249](../src/exporters/export-css-variables.ts)), so block order, which
  decides between equal-specificity selectors, is alphabetical rather than authored. `compiled.modes`
  cannot drive a theme picker in the author's order either.
- The executable theme-coordinate example authors `mono-light, mono-dark, vivid-light, vivid-dark`
  and asserts the canonical block order `mono-light, mono-dark, vivid-dark, vivid-light`
  ([theme.ts:151](../examples/theme-coordinates/theme.ts)).

A mode array is authored data, not incidental insertion order, and its order is equally
deterministic.

Recommendation: preserve authored order, optionally keeping the default mode first. Letting
`defaultMode` default to the first mode would shorten the envelope to `modes: [...]`, but it reverses
a settled rule and needs its own decision.

Severity: Low–Medium. Breaking for canonical serialization and CSS block order.

### 1.6 `defineTokens` and `defineTokenGraph` are equivalent

Evidence:

- `defineTokens` validates its options against the same key set as `defineTokenGraph`, including
  `layers` and `$schema` ([graph.ts:228-235, 273-289](../src/core/graph.ts)). Probe A9 composes a
  layer through `defineTokens`.
- The documented split, "the ordinary trusted token graph path" versus "a trusted graph with
  explicit graph options or layers" ([public-api.md:9-10](./public-api.md), ADR 0009), does not
  exist in code. Two equivalent entry points contradict ADR 0002's "no competing equivalent form".

Original recommendation: make the documented distinction real by limiting `defineTokens` options to
`modes`, `defaultMode`, and `defaultVisibility`, while `defineTokenGraph` keeps `layers` and
`$schema`. Collapsing to one helper was the alternative.

Revised by the design pass: keep `defineTokens` as the only graph helper and remove
`defineTokenGraph` ([ADR 0013](./adr/0013-coherent-token-model.md), D2). Restricting one helper so
that two names look different would remove a real capability. The production consumer uses
`defineTokenGraph` with a `material3` layer and migrates by renaming the call.

Severity: Low.

### 1.7 Schema identifier namespace

Already tracked by the [roadmap](./roadmap.md) and the consumer evidence audit: the project does not
control `scheme-tokens.dev`. Two observations sharpen the priority:

- Editors resolve `$schema` over HTTP. An artifact that carries `$schema` currently produces an
  unable-to-load-schema warning in VS Code.
- Parsers reject every other `$schema` value
  ([parse-token-graph.ts:1233-1251](../src/core/parse-token-graph.ts)), so moving to another
  identifier is a wire-format break. Registering the existing domain and hosting the exact packaged
  schema bytes, hash-checked by a release gate, is the least disruptive path.

Severity: Medium. Existing 1.0 gate.

### 1.8 Artifact evolution after 1.0

Parsers reject unknown properties and require `formatVersion: 1` exactly. Every additive field,
including the provenance chain in 3.3, therefore needs a new format version. Combined with the rule
against old-format readers, the first format revision after 1.0 would make persisted v1 artifacts
unreadable. That rule fits a greenfield 0.x line, not persisted artifacts after 1.0.

Recommendation: before 1.0, record how artifacts evolve. Options include reading versions N and N-1
for one major, or allowing additive optional fields within a version through an explicit extension
point.

Severity: Medium. A policy gap; deciding it requires no code change.

## 2. Developer experience

### 2.1 Export an `orThrow()` counterpart

Evidence:

- Seven documentation and example files declare their own `orThrow` or `expectOk`:
  `docs/diagnostics.md`, `docs/public-api.md`, `docs/tailwind-css-v4.md`, `docs-site/index.md`,
  `docs-site/guide/getting-started.md`, `docs-site/guide/export-css-variables.md`, and
  `examples/theme-coordinates/theme.ts`. Five of them hide the declaration in a twoslash cut.
- The README repeats the same `throw new Error(result.issues.map(…))` boilerplate five times
  ([README.md:48, 54, 235, 249, 394](../README.md)).
- Result-returning libraries in the ecosystem pair the safe form with a throwing one, such as Zod
  and Valibot `parse` next to `safeParse`.

ADR 0009 rejected `unwrap()` and `formatIssues()` because the application-local helper is easy to
write. The documentation is the counter-evidence: every entry point needs it. One export that throws
an `Error` carrying the original `issues` keeps the binary `Result` contract intact.

### 2.2 Infer visibility at the type level

Evidence:

- Default public compilation produces conservatively partial records. Getting Started therefore
  teaches exact keys first, and `maikel.site` uses exact `{ keys }` selection for its public output
  and `all` for Material role values, never the default selection.
- Ten files explain the partial typing: `docs/architecture.md`, `docs/migration.md`,
  `docs/public-api.md`, `docs/roadmap.md`, `docs-site/guide/export-css-variables.md`,
  `docs-site/guide/getting-started.md`, `docs-site/guide/migration.md`,
  `docs-site/guide/typescript-access.md`, `docs-site/reference/api.md`, and `AGENTS.md`.
- Probe B typechecks: public keys are inferred from literal authoring input while reference typos
  stay rejected.

Recommendation: prototype a public-key generic on `TokenGraph` and `TokenLayer`, apply layer order
and ADR 0011's visibility rules at the type level, and measure `tsc` time on the 308-token production
graph before committing. The prototype must also keep today's reference-typo diagnostic, which names
the offending key and adds TypeScript's own "Did you mean" suggestion; the probe's intersection-based
check rejects the same typo with a less direct message (Appendix B). Parsed graphs stay dynamic. If
it lands, most of the partial-typing explanation can go.

### 2.3 CSS export reports only the first issue

Every failure path in variable and block construction returns immediately
([export-css-variables.ts:176-311](../src/exporters/export-css-variables.ts)). Probe A6: three
declaration-unsafe values produce one `invalid-css-value` issue, for `a` only. The parsers collect
every issue. CSS export should collect issues the same way.

### 2.4 Smaller items

- Add "did you mean" suggestions to the runtime `unknown-reference` and `unknown-selection-key`
  messages. TypeScript already suggests the closest key for literal authoring (Appendix B), but
  parsed and dynamically built graphs get no suggestion. Messages are not contractual, so this fits
  a patch release. Probe A8 shows the current runtime message for the typo `brand.60`.
- Export `CssVariableNameInput`. A named `variableName` callback cannot import its parameter type
  today ([export-css-variables.ts:36](../src/exporters/export-css-variables.ts),
  [index.ts:33-41](../src/index.ts)).
- Attach structured issues (`cause`) to helper throws, using the parser codes and pointers, so tools
  can surface authoring errors without parsing messages.
- Document and test the TypeScript floor. The declarations use `NoInfer` (TypeScript 5.4) and
  `const` type parameters (TypeScript 5.0), but neither the README nor the gates state or test a
  minimum. TypeScript 7.0, the native compiler, has been generally available since 2026-07-08 and
  belongs in the packed-consumer type gate.
- `engines.node >=24` ([package.json:96](../package.json)) is a support policy rather than a
  technical need: the bundle targets ES2022 on the neutral platform, and Node 22 is still an LTS line
  (end of life scheduled for April 2027). Yarn classic fails installation on an engines mismatch.
- Type names mix `CssVar*` and `CssVariable*`. Issue codes stay as they are because they are
  contractual.
- A core parser message calls token values "authored CSS strings"
  ([parse-token-graph.ts:1128](../src/core/parse-token-graph.ts)), although core is value-agnostic.
- Unquoted data URIs that contain `;` are rejected as declaration-unsafe; quoting them works
  (probe A6). This is an acceptable bound, but it is not documented.

## 3. Features and extensions

### Within the core boundary

#### 3.1 Mode conditions in CSS export

The executable theme-coordinate example formats an extra `:root[data-scheme="light"]` block and an
`@media (prefers-color-scheme: dark) { :root:not([data-scheme]) { … } }` fallback by hand, outside
the exporter ([theme.ts:357-377](../examples/theme-coordinates/theme.ts)). A selector list can
already express the extra light selector, but not the fallback: the selector grammar accepts `:root`
only at the start of a compound selector, accepts no other pseudo-class, and accepts no at-rule
([selector-validation.ts:152-186](../src/exporters/selector-validation.ts)). Probe A4 lists the
accepted selector list and the rejected selectors. Terrazzo covers the same need with
`permutations`, including media queries.

Proposal: multiple selectors and a bounded `media` condition per mode, an optional `@layer` wrapper,
and a bounded grammar extension with `:where()`, `:is()`, `:not()`, `:host`, and `:host()`, whose
arguments reuse the same safe grammar. Design it with 1.4.

#### 3.2 Opt-in `var()` references

Style Dictionary's `outputReferences` emits `var(--target)` for references. Emit a reference only
when the target is part of the same export and fall back to the resolved value otherwise. Runtime
overrides then propagate on elements that also receive the mode block, such as `:root`. An override
on a subtree still requires dependants to be redeclared, which is why Terrazzo redeclares resolved
values. The option must document that limit.

#### 3.3 Provenance chain

`metadataByToken[key].origin` identifies only the winning declaration. Recording the replaced
declarations, for example as `shadowed: TokenOrigin[]`, answers "what did this override replace?"
directly. That is the question the headline provenance feature exists to answer
([agents-context.md](./agents-context.md)). The field is additive to the compiled format and
therefore depends on 1.8.

#### 3.4 Descriptive metadata in CSS

`description` and `deprecated` flow through compilation, but no output uses them (probe A10). An
opt-in comment mode in CSS export would make them visible where values are consumed.

### Sibling packages

#### 3.5 DTCG import

Figma has announced native DTCG import and export for variables, which makes DTCG the likely handoff
from design tools. The mapping is direct:

- groups become dot keys and aliases become references;
- `$description`, `$deprecated`, and `$extensions` become metadata;
- Resolver `sets` become ordered layers, since DTCG also lets the most recent occurrence win;
- a single modifier becomes modes, and several modifiers become flattened modes.

Structured DTCG values must be formatted to strings at the adapter boundary. The roadmap already
allows reconsidering DTCG import on demand.

#### 3.6 material3 extensions

- Custom colors with harmonization, such as success and warning, a common Material Theme Builder
  feature.
- The remaining `md.sys` token families next to color (typescale, shape, motion, state), so the
  output themes `@material/web` directly through its `--md-sys-*` custom properties.
- A configurable layer id so more than one fragment can compose in one graph. The fixed `material3`
  id currently limits a graph to one fragment ([ADR 0006](./adr/0006-material3-authoring-and-mode-contract.md)).

#### 3.7 Build integration

A Vite or unplugin integration can compile a `tokens.ts` graph module into a virtual CSS module with
hot reload.

#### 3.8 Contrast checks

`maikel.site` already produces a contrast report. A sibling package that checks declared
foreground/background pairs on compiled schemes could use provenance to name the override that broke
a pair.

### Needs a decision record first

#### 3.9 Explicit composite expressions

An expression such as `{ concat: ["0 0 0 1px ", { ref: "color.border" }] }` would cover shadows,
borders, `color-mix()`, and `calc()`. Output stays an opaque string and nothing is inferred from bare
strings, but `TokenExpression` widens, which AGENTS.md currently forbids. DTCG requires aliases to be
whole values; Style Dictionary and Panda resolve references inside strings.

#### 3.10 `@property` registration

Registering properties from an author-declared `syntax` lets theme switches transition. Core would
still not interpret values.

## 4. Decisions to retain

| Decision                                                                                     | Verdict                                                                                                                                                            |
| -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Compiler, not transformer; no platform exporters, CLI, or plugins in core                    | Retain. A clear niche next to Style Dictionary and Terrazzo.                                                                                                       |
| Opaque string values; no color model in core                                                 | Retain. The core differentiator.                                                                                                                                   |
| Explicit references; bare strings are never references                                       | Retain. Safer than reference parsing inside strings. Reference typos in graph tokens, including references to layer keys, already fail in the editor.              |
| No `$`-prefixed authoring namespace ([ADR 0003](./adr/0003-authoring-property-namespace.md)) | Retain. DTCG translation belongs at the adapter boundary.                                                                                                          |
| The graph owns modes; layers stay mode-unbound                                               | Retain.                                                                                                                                                            |
| Flat modes instead of axes                                                                   | Retain in the wire format. Watch item: DTCG modifiers and Figma collections are multi-axis, and flattening multiplies CSS output by the product of the axis sizes. |
| Binary `Result`; trusted helpers separate from untrusted parsers                             | Retain, complemented by 2.1.                                                                                                                                       |
| Bounded selector grammar                                                                     | Retain the principle; widen the grammar (3.1).                                                                                                                     |
| material3 as a sibling package with a pinned, bundled engine                                 | Retain.                                                                                                                                                            |

## 5. Internal redundancy

- Three parallel validation paths exist: authoring normalization in `graph.ts`,
  `parseTokenGraphArtifact`, and `parseTokenGraphInternal`. The artifact parser also runs the
  internal parser again on its own output ([parse-token-graph.ts:180](../src/core/parse-token-graph.ts)).
  Layer headers are parsed by `parseStandaloneLayer`, `parseLayerArtifact`, `parseGraphLayer`, and
  `copyStrictLayer`. One validator with throwing, `Result`, and compile front ends would reduce drift
  risk.
- Mode canonicalization exists four times (`graph.ts`, `parse-token-graph.ts`,
  `parse-compiled-scheme.ts`, `serialize-scheme.ts`) and reference detection three times.
- Dead code:
  - `isJsonSafeIssue` ([json.ts:153](../src/core/json.ts)), already finding 7 of the
    [2026-08 audit](./audit-2026-08.md);
  - `isExtensionKey` ([identifiers.ts:21](../src/core/identifiers.ts));
  - the unused `_leafKey` parameter ([compile-token-graph.ts:344](../src/core/compile-token-graph.ts));
  - the unreachable `missing-mode-selector` branch in block construction
    ([export-css-variables.ts:250-262](../src/exporters/export-css-variables.ts)), finding 8 of the
    2026-08 audit;
  - the `valueByMode` mode reservation ([graph.ts:97-104, 226](../src/core/graph.ts),
    [token-graph.v1.schema.json:57](../schemas/token-graph.v1.schema.json), and the documentation
    that lists reserved names). The mode pattern already rejects its uppercase letters (probe A7),
    so the reservation can never match.
- `tests/rnd/material3` (401 KB) keeps five fixtures that are byte-identical to
  `packages/material3/tests/fixtures`, only so ADR links stay stable. Commit permalinks are equally
  immutable.
- The partial-typing explanation is repeated in ten files (2.2). One canonical section with links
  would reduce drift.

## 6. Proposed sequence

Superseded by the release scope in [ADR 0013](./adr/0013-coherent-token-model.md). The original
sequence was:

1. **0.4, the last breaking window:** 1.1–1.6, decisions on 1.7 and 1.8, and the new CSS option
   shape together with mode conditions (3.1), so exporter options break once.
2. **1.0:** the existing evidence gates.
3. **1.x:** `orThrow` (2.1), type-level visibility (2.2), `var()` output (3.2), the provenance chain
   (3.3, subject to 1.8), and the sibling packages.

```js

  compileTokenGraph,
  defineTokenGraph,
  defineTokenLayer,
  defineTokens,
  exportCssVars,
  tokenRef,
} from "./dist/index.js";

const show = (label, value) => console.log(`${label}: ${JSON.stringify(value)}`);
const unwrap = (result) => {
  if (!result.ok) {
    throw new Error(JSON.stringify(result.issues));
  }
  return result.value;
};

// A1: a graph token and a layer declare the same key.
const generated = defineTokenLayer({ id: "generated", tokens: { "brand.primary": "#6750a4" } });
const a1 = unwrap(
  compileTokenGraph(
    defineTokenGraph({ tokens: { "brand.primary": "#ff0055" }, layers: [generated] }),
  ),
);
show("A1", {
  value: a1.tokens["brand.primary"],
  origin: a1.metadataByToken["brand.primary"].origin,
});

// A2: the material3 README override shape.
const material = defineTokenLayer({
  id: "material3",
  defaultVisibility: "internal",
  tokens: { "md.sys.color.primary": "#6750a4" },
});
const overrides = defineTokenLayer({
  id: "brand-overrides",
  tokens: { "md.sys.color.primary": "#ff0055" },
});
const a2 = unwrap(
  compileTokenGraph(
    defineTokenGraph({
      tokens: { "action.primary": tokenRef("md.sys.color.primary") },

    }),

);
show("A2 public keys", Object.keys(a2.tokens));
show("A2 css", unwrap(exportCssVars(a2)).css);
```

## Appendix B — type-level visibility probe

Superseded by Appendix A of [ADR 0013](./adr/0013-coherent-token-model.md), which compares four
signatures on TypeScript 5.9 and 6.0. This probe is kept as the record of the first attempt.

A standalone file that does not import the package. It checks that TypeScript can infer the public
key union from literal authoring input while an intersected mapped type still rejects reference
typos. Both `@ts-expect-error` directives are consumed and the command exits 0:

```sh
node node_modules/typescript/bin/tsc --noEmit --strict --target es2022 --module esnext --moduleResolution bundler visibility-probe.ts
```

```ts
type Ref<K extends string = string> = { readonly ref: K };
type Expr<K extends string> = string | Ref<K>;
type Expanded<K extends string> = {
  readonly value: Expr<K>;
  readonly visibility?: "public" | "internal";
  readonly description?: string;
};
type Authoring<K extends string> = Expr<K> | Expanded<K>;

type PublicKeys<T, Default extends "public" | "internal"> = {
  [P in keyof T]: T[P] extends { visibility: "internal" }
    ? never
    : T[P] extends { visibility: "public" }
      ? P
      : Default extends "public"
        ? P
        : never;
}[keyof T] &
  string;

interface Graph<Key extends string, Public extends string> {
  readonly tokens: Record<Key, unknown>;
  readonly __public?: Public;
}

declare function tokenRef<const K extends string>(key: K): Ref<K>;
declare function defineTokens<
  const T extends Record<string, Authoring<string>>,
  const D extends "public" | "internal" = "public",
>(
  tokens: T & { [P in keyof T]: Authoring<Extract<keyof T, string>> },
  options?: { defaultVisibility?: D },
): Graph<Extract<keyof T, string>, PublicKeys<T, D>>;
declare function compile<G extends Graph<string, string>>(
  graph: G,
): G extends Graph<string, infer P> ? Readonly<Record<P, string>> : never;

const graph = defineTokens({
  "brand.600": { value: "oklch(62% 0.18 250)", visibility: "internal" },
  "action.primary": tokenRef("brand.600"),
  surface: "#fff",
});
const compiled = compile(graph);
const a: string = compiled["action.primary"]; // complete, no optional access
const b: string = compiled.surface;
// @ts-expect-error internal key is not in the public record
compiled["brand.600"];

defineTokens({
  // @ts-expect-error reference typo is still rejected
  "action.primary": tokenRef("brand.60"),
  "brand.600": "#000",
});
void a;
void b;
```

Removing both directives shows that each fails for the intended reason: `TS7053` because
`"brand.600"` is not a key of the public record, and `TS2322` because `Ref<"brand.60">` is not
assignable to the token's authoring type. For the same typo, today's `NoInfer` signature reports:

```text
Type 'TokenReference<"brand.60">' is not assignable to type 'SingleTokenAuthoring<"action.primary" | "brand.600">'.
  Type 'TokenReference<"brand.60">' is not assignable to type 'TokenReference<"action.primary" | "brand.600">'.
    Type '"brand.60"' is not assignable to type '"action.primary" | "brand.600"'. Did you mean '"brand.600"'?
```

The probe's message instead names an intersection of the reference with the expanded-definition
type. The probe covers graph-level tokens only. Layers, mode maps, composition order, and diagnostic
quality still need the prototype described in 2.2.
