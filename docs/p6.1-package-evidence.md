# P6.1 package verification and compiler evidence

Scope: scheme-tokens and its Material package only. P6.1 supersedes external-migration requirements
in the active 0.4 plan and [historical P6 report](./p6-consumer-evidence.md). The implementation and
reproducible gates below own package completion. Final local aggregate and exact-SHA CI results
are recorded in the delivery report. P7 remains separately authorized and unstarted.

## Candidate verification

The patch boundary now retains a Buffer from Git, hashes it and saves those same bytes.
Only the commit identifier is trimmed; status and patches retain their whitespace. NUL-delimited
tracked paths preserve unusual filenames. SHA-256 records cover every existing tracked file.
Non-ignored untracked files and ignored untracked source/schema/Changesets inputs are rejected
with a useful tracking explanation. Staged additions are included; a tracked diff is never presented as
capturing untracked files. Ignored outputs are rebuilt. This records Git source and toolchain
provenance; arbitrary ignored inputs and a hermetic rebuild are not claimed.

The output directory must be empty and the shared pack helper rejects existing staging/pack
directories before building. No old tree is silently reused or deleted. Unit regressions use
disposable Git repositories to save and apply real text and binary changes, reconstruct exact
content, verify the patch digest, handle zero-byte empty diffs, reject untracked inputs and
reject reused staging directories.

The checker parses YAML with the exact development-only yaml dependency. It selects the project
document, supports pnpm lockfile version 9.0 and verifies the standalone importer `.` through
its dependency section, portable tarball specifier, resolved version, matching package entry
and integrity. Peer-qualified snapshots must exist and Material must resolve that same core.
Each artifact matches exactly one recorded provenance digest. Installed identities, versions,
Material peer ^0.4.0 and core realpath equality are checked independently.

Focused cases cover valid dependency/dev-dependency pairs, multiple YAML documents, swapped
integrities, wrong importer specifications and targets despite valid text elsewhere, missing or
mismatched resolutions, missing snapshots, artifact tampering, wrong lockfile core peers,
distinct installed cores, installed identity/version/peer drift and duplicate YAML keys.
These small structural fixtures are synthetic; the integration gate uses real paired tarballs.

`pnpm check:candidate` is part of `pnpm release:check` and both Node CI jobs. It packs the candidate,
checks the exact patch hash and reconstruction at its stated commit, creates a portable lock,
then copies only installation inputs into a second consumer without installed files. A frozen
strict-peer install uses a new dedicated store. The checker and both authoritative coordinate
examples run there with declaration emission. Lock and manifest inspection alone cannot prove
that stale installed runtime files match an artifact; this fresh installation provides the
complementary proof. No external application is used.

## Consumer compilers

[ADR 0017](./adr/0017-consumer-compiler-support.md) supersedes only ADR 0013 D13's compiler policy.
The bounded range is `>=5.9.3 <6.0.0 || >=6.0.2 <7.0.0 || >=7.0.2 <8.0.0` for both packages.
The repository keeps its exact TS7 development/build toolchain. Earlier patches and TS8 are
not claimed; TypeScript next remains non-blocking. No runtime/peer TypeScript dependency is added.

| Compiler role                           | Authoritative source                       | Actual paired packed declarations       | Stricter declaration emission            | Resolution/runtime                                       |
| --------------------------------------- | ------------------------------------------ | --------------------------------------- | ---------------------------------------- | -------------------------------------------------------- |
| TS5.9.3 consumer floor                  | Core seven-file and full Material matrices | Both matrices, strict-only and stricter | Source and packed, output files verified | Bundler, Node16, paired NodeNext and coordinate examples |
| TS6.0.2 consumer floor                  | Same matrices                              | Same matrices/configurations            | Same emission checks                     | Same resolution/runtime checks                           |
| TS7.0.2 floor and repository stable 7.x | Same matrices, deduplicated when equal     | Same matrices/configurations            | Same emission checks                     | Same resolution/runtime checks                           |
| TypeScript next                         | Same suite                                 | Same suite                              | Same emission checks                     | Non-blocking signal                                      |

Every check keeps skipLibCheck false, all negative authoring checks and positive inference
guarantees. Material retains the full P5.1 option-presence, explicit generic, optional input,
wrapper, contextual NoInfer and downstream selection regressions. Source profiles use the build's
Bundler resolution; the existing Material NodeNext declaration profile also remains. Source
engine declarations need DOM libraries, while packed consumers remain DOM-free. The stricter
consumer profiles retain exact optional properties, unchecked indexed access, verbatim module
syntax and isolated modules. Core's baseline declaration flag inherited noEmit true; the
corrected gate actually emits and verifies all seven declaration files.

The compatibility runner builds/project-packs one actual pair with TS7, then shares it across
compiler roles. Fresh frozen strict-peer consumers compile and execute the raw ESM/NodeNext
Material proof and the core-only/paired authoritative examples. CI has independently blocking
5.9, 6.0 and 7.x consumer jobs alongside the Node release, API and three-engine browser jobs.
The stable command runs every role; optional line selection supports focused investigation.

Implementation checks exposed configuration defects, not a need to weaken package types:
NodeNext cannot consume the build's extensionless source directly; separate Bundler source
profiles retain the existing NodeNext declaration checks. TS5.9 export-map emission and TS6
output layout require explicit project roots. Material source-only strict settings need the
engine's DOM declarations. Each was corrected without changing package declarations or negatives.

## Integration, scope and P7

The authoritative core-only coordinate example remains independent of Material; the paired
example retains its application-owned coordinates, exact mode/selection typing and structured
declaration fidelity. The existing external-named audit is explicitly synthetic repository-owned
package evidence. It never certifies or inspects an external application.

The maintained Tailwind guide now explains stock unlayered root/dark specificity. Stock values
belong in base; generated values are unlayered or in an explicitly later layer whose order is
declared before both stylesheets. The existing browser harness checks both stylesheet orders,
nested light/dark activation, actual colors and stock restoration after generated CSS removal.
An initial layered fixture declared its order too late in one placement; correcting the fixture
made all three engines pass without changing the exporter or any tolerance.

Historical external framework/scaffold failures and visual observations remain factual records.
No external migration, second Material demo, recovered scaffold, framework check or application
visual baseline is a release requirement. Existing external branches/worktrees are untouched.

P4a, P5 and P5.1 remain accepted. No runtime exports/semantics, static proof, Material options,
CSS projection/order, schemas/wire versions, engine algorithms, golden fixtures, licenses,
frozen oracle or fixed historical P4 fixture change. API snapshots remain unchanged. The compiler
support changeset accompanies the existing minor changesets, preserving temporary projection
to core 0.4.0 / Material 0.2.0 and peer ^0.4.0. Committed versions remain 0.3.0 / 0.1.1.

P7 must review the generated candidate changelogs and publication readiness, apply normal
versioning only with its authorization, and repeat the package gates on its final candidate.
No publication, tag, deployment, release, main merge or primary-worktree versioning is part of P6.1.
